# Архитектура монорепозитория

Монорепо объединяет публичный фронтенд на Next.js 16 (App Router) и бэкенд на Laravel 12 с админкой MoonShine 4 и PostgreSQL 18. Трафик всегда проходит через Nginx; оркестрация только через `docker/compose.sh`.

## Поток запросов (runtime)
```
Браузер → Nginx (:8080 dev / :80 prod)
  ├─ /admin, /api, /build, /storage, /vendor → php-fpm (backend-php) → PostgreSQL
  └─ остальное (/,_next, статические) → Next.js (frontend)
Next.js при загрузке данных дергает /api/* (через Nginx) → Laravel → PostgreSQL
```

## Фронтенд (директория `frontend/`)
- Next.js 16, App Router, SSR. Стилизация — TailwindCSS (utility `cn` в `src/lib/utils.ts`). Дизайн‑система под новый лендинг: Open Sans + Lorin, палитра brand.sky/orange/gradient start‑mid‑end, `shadow-glow`, `bg-brand-gradient`, новые анимации/токены в `app/globals.css` и `tailwind.config.js`. Safelist в `tailwind.config.js` генерирует `pt-[0..600px]`/`pb-[0..600px]` под произвольные паддинги из CMS.
- Главные маршруты:
- `/` (`app/page.tsx`) — лендинг теперь тоже приходит из сущности Pages: сервер тянет `/api/pages/home` и рендерит блоки через общий реестр. Если `type=product_landing` и в блоках нет `product_hero`, перед блоками добавляется ProductHero из связанного продукта. Формы подтягиваются только из `product.form` и блоков `product_hero` (`formsByCode`). При отсутствии записи slug `home` выводится мягкий плейсхолдер для админа. Данные для существующего лендинга миграцией `2025_12_03_000100_seed_home_page_from_static` автоматически создают опубликованную страницу `slug=home` с теми же блоками, что были в статике.
- `(marketing)/[slug]` — либо продуктовые лендинги (`type=product_landing`), либо статические страницы (`type=static`), данные с `/api/pages/{slug}`, блоковый рендер через реестр. Для `product_landing` дополнительно прилетает `product`, `variants`; перед блоками жестко рендерится `ProductHero` из продукта **только если** в блоках нет layout `product_hero` (чтобы избежать дубляжа). Конфиги форм подтягиваются на сервере для всех кодов, встреченных в продукте и в блоках `product_hero` (map `formsByCode` → передается в рендерер); QuoteModal работает без клиентского GET. Новый layout `product_hero` позволяет заполнить поля вручную и не опираться на Products API (`useProductData=false`), выбирать вариант бейджей (`badgeVariant=image|card`), задавать только изображения + подпись (без icon key); CTA показывается при наличии `formCode`, даже если страница статичная и продукта нет; если `useProductData=true` и продукта нет, CTA скрывается. При желании можно оставить автозаполнение из `product` (`useProductData=true`). Games блоки берут игры из сущности `Game` (авто — все/limit, ручной — выбранные slug’и из выпадающего списка).
  - `/news` и `/news/[...slug]` — список статей `type=news` и детальная статья по slug последнего сегмента.
  - `/case-studies` — список `type=case_study`, карточки ведут на `/news/{slug}`.
  - `/games` и `/games/[slug]` — каталог игр и детали.
- `/store` и `/store/[slug]` — каталог и карточка StoreProduct.
- `/case-studies` — список кейсов (articles type=case_study) на Tailwind/shadcn `Card`.
- Конфиг: `next.config.mjs` (`output: "standalone"`). В dev переписывает `/api/*` на `http://nginx/api/*` или `NEXT_API_PROXY`; в прод переписываний нет.
- Глобальный каркас `app/layout.tsx` выводит шапку/футер (`src/components/layout/SiteHeader|SiteFooter`), поднимает меню `header`/`footer` из `/api/menus` (helpers `src/lib/menus.ts`, revalidate 300s) и применяет шрифты `Open Sans`/`Lorin`. Header — двухуровневый sticky (40px синий топ-бар + 60px белый основной), контейнеры `max-w-[1189px]` (2xl `1320px`, без внутренних паддингов на 2xl) с центральным слотом под логотип 110×100; нижний ряд — сетка `1fr/auto/1fr` с адаптивными зазорами: `48/80/120px` слева и `50/80/95px` справа (переключение на мобильный режим при ширине <1000px). Mega‑menu рендерится для первого пункта с `children` (по данным API), привязки к тексту нет. Мобильный дровер: стрелка показывается только у пунктов с вложениями; иерархия дочерних пунктов выводится двумя уровнями (группа → элементы). Footer — рефреш из дизайн-системы, но column “Helpful links” и соцссылки берутся из меню `footer`/`social` с fallback. Палитра/градиенты задаются в `globals.css`.
- SEO-база: переехали на `next-seo` + `next-sitemap`. `src/lib/seo.ts` конвертирует конфиг `next-seo.config.ts` (titleTemplate, OG/Twitter, canonical из `NEXT_PUBLIC_SITE_URL`) в `Metadata`; `DefaultSeo` подключён в `app/layout.tsx`. Динамические страницы собирают `Metadata` через `mergeSeo`/`nextSeoToMetadata`. JSON-LD остаётся для статей (NewsArticle), игр (VideoGame) и товаров магазина (Product). robots/sitemap теперь генерируются postbuild через `next-sitemap` (конфиг `next-sitemap.config.js` с выборкой статичных путей + articles/games(is_indexable)/store products из API); статические файлы лежат в `public/` после билда, отдельные маршруты `app/robots.ts`/`app/sitemap.ts` удалены. Стили — брендовые HSL-токены в `app/globals.css`, Tailwind config `tailwind.config.js`, postcss конфиг `postcss.config.js`.
- Переменные окружения, доступные клиенту: `NEXT_PUBLIC_API_URL` (по умолчанию `http://localhost:8080/api`; в прод‑компоузе прокидываем `http://nginx/api`, чтобы SSR ходил к Laravel через Nginx внутри сети compose), `NEXT_PUBLIC_SITE_URL` (для `next-seo`/`next-sitemap`; fallback `https://kidsjumptech.com`), опционально `SITEMAP_API_BASE` для генерации sitemap.
- Блоковый рендерер: типы → `src/lib/blocks/types.ts` (перенесены из прежнего design), реестр `src/lib/blocks/registry.tsx` рендерит блоки новым набором дизайн-компонентов (Hero, HeroValueGrid, FeatureGrid, ProductHero, ProductCarousel, GamesGallery, **GamesGrid**, News, Stats, FAQ, WhyUs, ProductDescription, ProductNav, OurApproach, ProductSpecs, CompareModels, CTASection, HighlightCTA, Reviews, TrustedBy) из `src/components/blocks`. При рендере каждый блок оборачивается в `div id=<anchor>` с автогенерацией якоря: приоритет `values.anchor` → пресет по имени лэйаута (hero/description/specs/compare/approach/faq/cta/etc) → slug заголовка → slug имени лэйаута; slugifier транслитерирует кириллицу и чистит не‑ASCII, дубликаты получают суффиксы `-2`, `-3`. Формат данных API прежний `{ name, key, values }`, маппинг на новый дизайн идёт по `name`. Legacy/shadcn блоки удалены; поддерживаются только текущие компоненты. В админке для всех layout теперь одно текстовое поле `padding` (строка с классами/inline-стилями Tailwind), которое полностью заменяет дефолтные паддинги секции; при пустом значении фронт применяет свои дефолты. Числовых `padding.top/bottom` больше нет.
- Layout `interactive_header` теперь рендерится компонентом `InteractiveShowcase` (две карточки: текст + фото/видео с чередованием колонок, плитка фич, CTA + галерея/видео-модалки). Пропсы: `items[{ title, productPageSlug?, description (rich text), hashtag, features[{ icons?[], label }], ctaLabel, formCode?, gallery[{src,alt}], videoId? }]`, `padding`, `defaultFormCode`, `formConfig`. В админке каждая feature имеет фиксированные поля `icon1|icon2|icon3` (Image) + `label` — никаких `Image::multiple()` внутри Json (MoonShine падает из-за `ComponentSlot::__toString()`), поэтому бэкенд при отдаче API собирает `icons[]` из непустых `icon1..3` и добавляет туда легаси `icons[]`, если они были. FeatureCard рисует все элементы массива `icons` без лимита. Видео-превью берётся из YouTube (`https://img.youtube.com/vi/<id>/maxresdefault.jpg`), без ручных постеров/alt. CTA работает только при наличии `formCode` (или `defaultFormCode`), всегда открывает QuoteModal; без формы кнопка скрывается. Если задан `productPageSlug`, заголовок ведёт на соответствующую product_landing страницу (`/${slug}`). Автоподстановка пресетов не используется; данные приходят из админки MoonShine.
- Динамическое SEO: `generateMetadata` на маркетинговых, новостных, игровых и store‑страницах читает SEO-поля из API-ответов.

## Бэкенд Laravel (директория `backend/`)
- Вход: `public/index.php`; API и админка обслуживаются через Nginx.
- Основные маршруты (`routes/api.php`):
  - `GET /api/health` → `{ ok: true }`
  - `GET /api/menus?location=header|footer` — активные меню с вложенными пунктами (`label`, `url`, `slot`, `icon`, `opens_in_new_tab`, `children`).
  - Контентные страницы: `GET /api/pages/{slug}` — только `status=published`, ответ `PageResource` (`slug`, `title`, `type`, `seo{title,description,canonical,og_image}`, `blocks[{name,key,values}]`); API не перекладывает их в `layout/fields`, фронт сам мапит `name→layout`, `values→fields` при рендере.
  - Статьи: `GET /api/articles?type&category&limit&page`, `GET /api/articles/{slug}` — только опубликованные; `ArticleResource` включает SEO и категории.
  - Игры: `GET /api/games?limit`, `GET /api/games/{slug}` (`GameResource`, категории, products_used, game_type, video_id, video_url, is_indexable).
  - Продукты-лендинги: `GET /api/products?limit`, `GET /api/products/{slug}` (`ProductResource` с variants + industries).
  - Магазин: `GET /api/store/products?limit&available`, `GET /api/store/products/{slug}` (`StoreProductResource` с категориями, доступностью, specs).
  - Отзывы: `GET /api/reviews?limit&fields&filter[ids]=1,2&filter[is_active]=true` — по умолчанию только активные, сортировка `position` → `review_date` → `id`; отдаёт name/date/rating/text/avatar/source_url/position/is_active.
  - Формы: `GET /api/forms/{code}` — возвращает `code`, `title`, `topic`, `submit_label`, `success_message`, `fields[]` (name/label/type/options/required); `POST /api/forms/{code}` — принимает `topic` (из запроса или из формы), валидирует обязательные поля (email + required из `forms.config`), создаёт `Lead` с `topic`, `payload`, `source_url`, `utm`, `submitted_at` (timestamp сервера), ответ `{ success: true }` 201.
- Веб-роут `/` (стандартный `welcome`), остальное закрыто MoonShine.

### MoonShine (админка)
- Провайдер `App\Providers\MoonShineServiceProvider` регистрирует все ресурсы; layout `App\MoonShine\Layouts\MoonShineLayout` (палитра Purple, кастомное меню). В `App\Providers\AppServiceProvider` вручную регистрируем `MoonShine\TinyMce\Providers\TinyMceServiceProvider`, т.к. auto-discovery его не подтягивает и без него падают TinyMCE-поля в админке.
- Адрес админки: `/admin` (prefix из `config/moonshine.php`), аутентификация `moonshine` guard.
- Ресурсы (CRUD):
  - **Контент:** `PageResource` (конструктор блоков: hero, features_grid, games_list, news_list, quote_form), `ArticleResource` (типы: news/case_study/blog/in_press, категории m2m), `ArticleCategoryResource` (иерархия категорий).
  - **Игры:** `GameResource` (genre/target_age, hero_image, m2m категории), `GameCategoryResource`.
- **Продукты:** `ProductResource` (rating/review_count_label, badges json — на детальной странице выводится стандартным Json без `->unescape()` (у поля нет такого метода), form belongsTo Form, industries m2m; без SEO-полей), `ProductVariantResource` (image upload `products/variants`, price/specs JSON, сортировка `position`; specs выводятся как таблица key→value), `IndustryResource` (группы government/healthcare/public/other).
- **Продукты:** `ProductResource` (industries m2m; без SEO-полей), `ProductVariantResource` (image upload, price/specs JSON, сортировка `position`; specs редактируются в табличном JSON-поле `specs_table`: строки key/value/type(string|number|boolean|json), которые при сохранении собираются обратно в ассоциативный массив `specs`; на списке выводится превью `image` с диска `public/products/variants`, экспорт работает по умолчанию).
- Все поля `Slug` в MoonShine ресурсах генерируются реактивно от `title`/`name` с локалью `ru` (транслитерация кириллицы) без задержки, но при наличии собственного значения slug не перезаписывается.
- В `Page`/`Article` формах `Published at` по умолчанию проставляется текущим временем; при сохранении записи в статусе `published` пустое поле также автозаполняется на уровне модели.
- **Магазин:** `StoreProductResource` (availability switcher, price, categories m2m), `StoreCategoryResource` (self-parent).
- **Формы и лиды:** `FormResource` (topic, JSON-конфиг форм: submit_label, success_message, поля с типами text/email/phone/textarea/select/checkbox), `LeadResource` (topic, payload, utm JSON; деталь выводит payload/utm таблицей key→value плюс source_url, submitted_at и связанный product_variant; в списке лидов включён мультивыбор с массовым удалением как в остальных ресурсах).
- **Отзывы:** `ReviewResource` (name, review_date, rating 1–5, текст TinyMCE, аватар upload в `storage/app/public/reviews` с валидацией `image|max:5MB`, source_url, position, active).
- **Навигация:** `MenuResource` (создание/активация меню с локацией header/footer) и `MenuItemResource` (пункты со слотами, иконками, таргетами, вложенностью и позицией; URL опционален — пустое значение делает пункт не кликабельным). Индекс Menu Items теперь дерево с drag-and-drop сортировкой (MoonShine Tree Resource) и принудительной фильтрацией по выбранному меню; в форме Parent выбирается из элементов текущего меню. Штатные фильтры MoonShine не работают с TreeComponent, поэтому на странице дерева есть собственный OffCanvas-фильтр (кнопка Filters в топ-баре) с полями menu/slot/parent; `MenuItemResource::modifyQueryBuilder` вручную применяет `filters[menu|slot|parent]` и подставляет первый доступный `menu_id` по умолчанию.
- **Системные:** `MoonShineUserResource`, `MoonShineUserRoleResource` (стандартные ресурсы пакета).
- **Деревья с drag-and-drop:** `ArticleCategoryResource`, `StoreCategoryResource` и `MenuItemResource` переведены на `lee-to/moonshine-tree-resource` (MoonShine v4). Индекс-страницы теперь рисуют дерево с сортировкой перетаскиванием и автоматическим сохранением `position`; массовое удаление отключено. Меню-дерево всегда фильтруется по выбранному меню (по умолчанию первый), новые узлы получают позицию в конце ветки, поле `Position` из формы меню убрано.
- В `PageFormPage` у конструктора блоков включён кастомный `onApply` для `Layouts`, чтобы MoonShine сохраняла dot-ключи вложенных полей (`padding`, `query.*`) из `blocks[...]` как есть; ранее они затирались пустыми строками при сохранении. Поле `padding` теперь одно строковое (класс/стили Tailwind); пустое значение оставляет дефолтные отступы блока.
- Все CRUD-страницы используют валидации уникальности slug/code и базовые required-правила; загрузки файлов ведутся на диск `public` в подкаталоги `seo/`, `pages/hero`, `articles`, `games`, `products`, `store`.

## Инфраструктура
- **Оркестрация:** `docker/compose.sh <environment> …` (обязательное использование). Композ-файлы: `docker/development.compose.yml`, `docker/production.compose.yml`. Env-файлы: `.env.development`, `.env.production`.
- **Сервисы (dev):**
  - `frontend`: Next dev server на 3000, код смонтирован.
  - `backend-php`: PHP-FPM 8.3, Laravel код смонтирован; общий volume `storage` монтируется в `/var/www/backend/storage` для пользовательских файлов. Лимит памяти PHP в dev поднят до `512M` через `php.dev.ini` → `/usr/local/etc/php/conf.d/php-memory.ini`.
  - `nginx`: слушает :8080, подхватывает `nginx/nginx.dev.conf`, маунты `backend/public` и общий volume `storage` (RO) для раздачи `/storage`.
  - `postgres`: `postgres:18-alpine`, volume `postgres-data`.
- **Сервисы (prod):** сборка prod-образов Next/Laravel/Nginx, порт :80; `APP_DEBUG=false`.
  - `backend-php` и `nginx` разделяют volume `storage`, чтобы загруженные через Laravel файлы (`storage/app/public`) сразу раздавались по `/storage/*`. Лимит памяти PHP в prod выставлен на `256M` через `php.prod.ini` → `/usr/local/etc/php/conf.d/php-memory.ini`.
  - В `nginx.prod.conf` `/storage/` настроен через `alias` на `storage/app/public` (без проксирования в PHP) с CORS `Access-Control-Allow-Origin: *`.
- **Nginx:** `nginx/nginx.*.conf` — роутинг `/admin` и `/api` в php-fpm, статические Laravel ассеты (`/build`,`/storage`,`/vendor`) обслуживаются напрямую; `/storage/*` отдаётся напрямую из volume `storage/app/public` (без `try_files` и php-fpm, с CORS `*` и кешом 7d), остальное проксируется в Next (в prod кэширование выключено через `proxy_cache_bypass`). Блокировка индексации убрана: X-Robots-Tag не выставляется, `/robots.txt` и `sitemap*.xml` раздаются как статические файлы, сгенерированные `next-sitemap`.
- **База данных:** host `postgres`, port `5432`; миграции покрывают все сущности, дополнительные изменения в схеме допускаются только через миграции.

## Взаимодействие данных
- Публичные страницы, новости, кейсы, игры и каталог читаются с Laravel API (pages/articles/games/products/store_products) через Next.js `fetch`/`renderBlocks`; хедер/футер подтягивают меню `header`/`footer` с `/api/menus` (fallback на статические пресеты при пустом ответе).
- API нормализует медиа-пути через `Storage::disk('public')->url`, поэтому `hero_image`/`featured_image`/`og_image`/`image` уже приходят как `/storage/...` или абсолютный URL и могут использоваться фронтом напрямую. Все публичные эндпоинты поддерживают опциональные `filter[field]=value` (белый список на уровне контроллеров) и `fields=slug,name,...` для выборки ограниченного набора полей без изменения базового функционала.
- Слайдер «Trusted by»: сущность `TrustedLogo` (таблица `trusted_logos`, поля image, alt, is_active, position), управление в админке через MoonShine (ресурс TrustedLogoResource, загрузка в `storage/app/public/trusted-logos`), публичный API `GET /api/trusted-logos` возвращает активные логотипы по position.
- Отзывы для блока `Reviews`: сущность `Review` (CRUD в админке, меню `Reviews`), публичный API `GET /api/reviews` (по умолчанию активные, сортировка position → review_date → id, фильтры ids/rating/is_active, fields). Блок на фронте всегда сам загружает данные из API (опциональный `query{limit,fields,ids,onlyActive}`), внешние `items` не принимаются. Поддерживается параметр `template` (`featured` | `compact`): `featured` — только крупный слайдер 2×434px (≥1024px) / 1×468px (mobile) с точками; `compact` — блок средней оценки + количества отзывов и компактный слайдер (3 колонки ≥1280, 2 ≥1024, 1 на mobile). Цвета/градиенты: фон `brand.gray`, текст `brand.dark`, звёзды `ui.star`, CTA использует `bg-brand-gradient animate-gradient` как в кнопке Live demo. Радиус карточек 10px, тень `0 2px 20.6px rgba(0,0,0,0.1)`, текст в карточках ограничен по высоте, при переполнении доступен скролл без затемнения.
- Структурированные контент-блоки страниц (`pages.blocks`) сохраняются в формате MoonShine Layouts (`{ name, key, values }`, каст LayoutsCast). Актуальные layout'ы в админке: hero (title, slides[videoId,alt]), **page_header** (title; фон `bg-brand-gray`, градиентный H1; опциональный `padding` строкой классов), **hero_values** (title/subtitle/text/cta + items{title,description,icon}; `icon` загружается как SVG-файл в `public/storage/pages/hero_values/icons` и на фронте рисуется `<img>`; columns настраивается, цвет/вариант фиксированы как в дизайн-референсе — sky/values), **product_hero** (title/slogan/description/rating/reviewCount/badgeVariant=image|card/badges[{image,label}]/ctaLabel/formCode/formTitle; `formCode` выбирается из сущности Forms в админке и при наличии перекрывает product.form.code; опция `useProductData=true|false`, CTA показывается всегда при наличии `formCode` (для статичных страниц без продукта тоже), но если `useProductData=true` и продукт не пришёл, CTA не рендерится; при указании `formCode` форма подтягивается на сервере), product_description (title/description), product_nav (items[{label,anchor}] — навигация по якорям секций, anchor задаётся без `#`, компонент сам вычитает оффсет хедера), our_approach (title/description, иллюстрация с концентрическими кольцами и иконками чувств), product_specs (tabs[{key,label,image,title,description}] — `key` is a required slug-like tab identifier (latin, no spaces); `label` is the visible tab caption), compare_models (title/description; таблица строится автоматически из product.variants на странице продукта), feature_grid (title + HTML description via RichText + items{title,description,icon}/columns; `icon` — файл из админки, фронт рендерит `<img>` 46–60px), product_carousel (title/description/query{limit/fields/filter}), games_gallery (title + HTML description via RichText + query), **games_grid** (title/description + query{limit/fields/filter[slug|title|genre|target_age|game_type|is_indexable|video_id]}, фронт выводит плитки с категориями по `game_type`/genre, Play-оверлеем и модальным YouTube-плеером по `video_id`, кнопка “Load More” подгружает следующие страницы `/api/games`), **game_detail** (slug игры; фронт сам тянет `/api/games/{slug}`, выводит PageHeader с кастомным цветом, видео в модалке по `video_id`, жанр/target_age, ссылки на связанные продукты, описание из body/excerpt, навигация Prev/Next внутри того же жанра), news (title/description/query), stats (title/description/items{value,label}), faq (title/items{question,answer}), why_us (title/description), cta_section (title/description/cta + textColorClass + backgroundImage), highlight_cta (title/description/cta), reviews (title/description/cta + query{limit/fields/ids/onlyActive}), trusted_by (title + HTML description via RichText + footer_text + query.fields). Легаси layouts (games_list, quote_form, icon_bullets, logos, comparison_table, use_cases, reviews_feed, product_cards, social_proof) удалены из конструктора; FAQ реализован заново отдельным блоком. API отдаёт тот же формат; фронт мапит `name` → новый дизайн‑компонент. Блоки существующих страниц приведены к новому формату (hero/hero_values/feature_grid/games_gallery/stats) без легаси-полей.
- Формы: структура хранится в `forms.config`, отправленные данные валидируются на бэкенде, сохраняются в `leads.topic` + `leads.payload`/`utm`; связь по `form_code`. `topic` берётся из запроса (например, название блока в InteractiveShowcase) либо из самой формы, и также пробрасывается в payload, если не было явного поля `topic`. Конфиг формы фронт получает на сервере Next через `GET /api/forms/{code}` (не виден в DevTools пользователя) и передает поля в клиентскую часть; в браузере выполняется только `POST /api/forms/{code}`. В админке MoonShine payload/utm показываются как таблицы key→value на детальной странице лида. Конфиг может включать `topic`, `submit_label` и `success_message` для текста кнопки/ответа.
- В админке MoonShine все описания/Body остаются на WYSIWYG `TinyMce` (`moonshine/tinymce`, с `->unescape()`); SEO-блоки: `SEO Title` с `->unescape()`, `SEO Description` — `Textarea` с `->unescape()` (без TinyMCE), чтобы править мета-тексты без редактора, но с многострочным вводом.
- Повторяемые JSON-поля в админке (конфиг форм, спецификации варианта, бейджи продукта, списки/фильтры блоков страницы и их вложенные коллекции) теперь рендерятся в стандартной табличной форме (горизонтально). Это убирает падение PHP 8.3 `ComponentSlot::__toString()` на PageFormPage, которое возникало из-за передачи UI-компонентов в слот при вертикальном режиме. Дополнительно, в layout `interactive_header` мы убрали `Image::multiple()` внутри Json (fixed `icon1..3`) — MoonShine сейчас не умеет рендерить `Components` коллекции в ячейке Json-таблицы, поэтому multi-upload приводил к той же ошибке.
- ProductHero на `product_landing` берет `form.code` из `Product.form` и открывает клиентский QuoteModal: конфиг формы (`/api/forms/{code}`) подтягивается на сервере Next в `(marketing)/[slug]/page.tsx` и пробрасывается в QuoteModal; в браузере выполняется только `POST /api/forms/{code}` с `topic`, `source_url` и `utm` (topic берётся из пропсов/формы).
- API форм: `GET /api/forms/{code}` отдает `{ code, title, topic, submit_label, success_message, fields[] }` (fields: name/label/type/required/options), `POST /api/forms/{code}` принимает значения полей + `topic`, `source_url`, `utm` JSON; дефолтные поля email/name/message отдаются, если конфиг пуст.

## Работа и дальнейшее расширение
- Для локального запуска соблюдайте контракт: проверяйте `./docker/compose.sh development ps`, далее `./docker/compose.sh development up --build` при необходимости.
- Новые схемы добавляйте миграциями; новые админские CRUD — через MoonShine resources (при генерации прописывать в `MoonShineServiceProvider` и меню `MoonShineLayout`).
- Ключевые точки расширения фронтенда: подключение новых API (pages, articles, products), использование `NEXT_PUBLIC_API_URL` для прокси через Nginx.
