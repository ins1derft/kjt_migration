# Введение

Это руководство объясняет, как работать с админ‑панелью MoonShine: где находится каждый раздел, что означает каждое поле, и как безопасно вносить изменения, чтобы они корректно отображались на сайте.

Админ‑панель — это интерфейс управления данными (сущностями) проекта: страницами, новостями, продуктами, формами, заявками и настройками сайта.

## Карта сущностей (что с чем связано)

Ниже — упрощённая схема, которая помогает понимать последствия изменений:

- **Pages** → основной конструктор контента страниц сайта (страницы состоят из блоков).
  - страница может быть **Static** (обычная) или **Product landing** (продуктовая, связана с продуктом).
- **Articles** ↔ **Article Categories** → новости/публикации и их категории (категории могут быть вложенными).
- **Games** ↔ **Game Categories** → игры и категории игр (используются для подборок/выводов в блоках страниц).
- **Products** → базовая сущность продукта.
  - **Product Variants** → варианты/комплектации продукта (обычно выводятся на продуктовых страницах).
  - **Product Attributes** → справочник характеристик; значения атрибутов заполняются на вариантах.
  - **Forms** → продукт может быть связан с формой (CTA “Get a quote/Live demo”).
- **Forms** → шаблоны форм → **Leads** → заявки (результат отправки форм с сайта).
- **Site settings** → единые контакты/соцсети/логотип и прочие общие настройки.
- **Menus** → наборы меню (header/footer) → **Menu Items** → пункты меню в виде дерева.
- Дополнительно: **Store Products/Store Categories** (если используется магазин), **Reviews**, **Trusted Logos**, **Sensory Room Bundles**, **Team**.

## Важно

- Перед началом работы убедитесь, что у вас есть доступ (логин/пароль) к админ‑панели. Пароли обычно выдаются отдельно и не публикуются в документации.
- Все изменения вступают в силу после сохранения. Для сущностей со статусом (draft/published) дополнительно проверьте статус публикации.
- После изменений всегда проверяйте результат на сайте (в новой вкладке) — так вы сразу увидите, что контент отображается правильно.

# Доступ и вход

## Адрес админ‑панели

- Админ‑панель доступна по адресу: `/admin`
- Пример (локально): `http://localhost:8080/admin`

![Экран входа в админ‑панель](screenshots/00-login.png)

## Вход

1. Откройте `/admin`.
2. Введите **Username** и **Password** (учётные данные выдаются администратором).
3. Нажмите **Log in**.

## Выход

1. Нажмите на аватар/кнопку пользователя в правом верхнем углу.
2. Нажмите **Log out**.

# Публикация и проверка изменений

## Статусы (draft/published)

Некоторые сущности (например, страницы и материалы) имеют статус. Логика обычно такая:

- **draft** — черновик, может не отображаться на сайте (или отображаться ограниченно).
- **published** — опубликовано и отображается на сайте.

Рекомендация: после сохранения всегда проверьте, что нужный статус выставлен корректно.

## Проверка результата на сайте

Практика, которая экономит время:

1. Сохраните изменения в админ‑панели (**Save**).
2. Откройте соответствующую страницу на сайте (по URL/slug).
3. Проверьте отображение (текст, картинки, порядок блоков, ссылки).

# Общие сценарии работы

## Создание записи

1. Откройте нужный раздел в меню слева.
2. Нажмите **Create**.
3. Заполните обязательные поля (обычно помечены `*`).
4. Нажмите **Save**.

## Редактирование записи

1. Откройте раздел.
2. В таблице найдите запись (по поиску/фильтрам).
3. Нажмите **Edit**.
4. Внесите изменения → **Save**.

## Удаление записи

1. Откройте раздел.
2. Нажмите иконку удаления у записи.
3. Подтвердите действие.

Рекомендация: перед удалением убедитесь, что запись нигде не используется (например, статья может быть привязана к странице или категориям).

## Загрузка изображений и файлов

Во многих сущностях есть поля типа Image/File:

- Нажмите в поле загрузки и выберите файл.
- После сохранения файл будет храниться в системе.
- Если доступна кнопка удаления (Remove), можно удалить файл из поля и сохранить запись.

## Деревья (иерархии)

Часть сущностей управляется в виде дерева (родитель → дочерние элементы). В таких разделах обычно:

- элементы можно раскрывать/сворачивать,
- порядок (position) влияет на сортировку,
- у элемента может быть Parent (родитель).

# Сущности и разделы (по меню)

Ниже приведены ключевые разделы админ‑панели и их назначение.

## Pages (Страницы)

**Назначение:** управление страницами сайта и их блоками (конструктор блоков).

**Где используется на сайте:** главная `/` и маркетинговые страницы `/{slug}` (в зависимости от типа страницы).

![Pages — список](screenshots/03-pages-index.png)

![Pages — форма редактирования](screenshots/04-pages-form.png)

### Ключевые поля

- **Slug** — адрес страницы (например, `home` для главной).
- **Title** — заголовок страницы.
- **Type** — тип страницы (например, статическая или продуктовая).
- **Status** — черновик/публикация.
- **Blocks** — набор блоков (контент‑конструктор).
- **SEO** — мета‑поля для поисковых систем (если заполнены).

### Slug: как влияет на адрес страницы

- `slug=home` используется как главная страница сайта (`/`).
- Любой другой slug обычно соответствует адресу `/{slug}`.

Рекомендация: используйте короткие slug латиницей, без пробелов. Следите за уникальностью.

### Type: статическая vs продуктовая

Тип страницы влияет на то, какие данные и блоки участвуют в рендере:

- **Static** — обычная страница: контент полностью задаётся блоками (Blocks).
- **Product landing** — продуктовая: может быть связана с **Product** и/или формой (CTA), и на сайте дополнительно может выводиться “hero” продукта/варианты (в зависимости от конфигурации блоков).

Если страница “не выглядит как ожидалось”, проверьте:

1. правильный **Type**,
2. заполнен ли связанный **Product** (если нужен),
3. не дублируется ли hero/CTA (например, одновременно в блоках и автогенерацией).

### Работа с блоками (Blocks)

1. В блоках нажмите **Add layout** и выберите нужный блок.
2. Заполните поля блока.
3. Сохраните страницу (**Save**).

![Добавление блока (Add layout)](screenshots/05-pages-add-layout.png)

Дополнительные возможности конструктора:

- **Перетаскивание**: блоки можно менять местами (порядок влияет на отображение на сайте).
- **Copy/Paste**: у блоков может быть быстрый перенос (копирование блока и вставка на другую страницу) — удобно для повторяющихся секций.

Рекомендация: вносите изменения небольшими порциями и сразу проверяйте страницу на сайте по её `slug`.

**Назначение:** справочник атрибутов (характеристик), которые затем заполняются на вариантах продукта и используются в таблицах сравнения/спецификациях.

## Product Variants (Варианты продукта)

**Назначение:** варианты одного продукта (например, комплектации/пакеты), с ценой, картинкой и набором атрибутов.

![Product Variants — список](screenshots/18-product-variants-index.png)

![Product Variants — форма](screenshots/19-product-variants-form.png)

### Ключевые поля

- **Product** — к какому продукту относится вариант.
- **Name** — название варианта.
- **Image** — изображение.
- **Price** — цена (если используется).
- **Label** — короткая подпись/бейдж.
- **Highlight in Compare Table** — выделить вариант в таблице сравнения.
- **Attributes** — значения характеристик, сгруппированные по типам (string/number/boolean/json).

Рекомендация: сначала заведите **Product Attributes**, затем заполняйте их значения на **Product Variants**.

Подсказка по JSON‑атрибутам: они часто задаются в формате key/value (например, список параметров), чтобы на сайте можно было красиво отрисовать спецификации.

## Forms (Формы)

**Назначение:** шаблоны форм, которые используются на фронтенде (например, в модальном окне “Get a quote”). Здесь настраиваются поля, подписи, сообщения об успехе и многошаговые сценарии.

![Forms — список](screenshots/26-forms-index.png)

![Forms — редактирование (верх формы)](screenshots/27-forms-edit-top.png)

![Forms — конфигурация полей/опций/шагов](screenshots/42-forms-config-fields.png)

### Основные поля формы

- **Code** — уникальный код формы (используется фронтендом), например `live_demo`.
- **Title** — название формы (для админки/интерфейса).
- **Topic** — тема (может подставляться в заявки по умолчанию).

### Config → Submit label / Success message / Disclaimer

- **Submit label** — текст на кнопке отправки.
- **Success message** — сообщение после успешной отправки.
- **Disclaimer** — текст под формой (политика/согласие и т.п.).

### Config → Fields

Каждое поле формы задаётся строкой в **Fields**:

- **Name** — системное имя (ключ).
- **Label** — подпись для пользователя.
- **Type** — тип поля (`text`, `email`, `phone`, `date`, `file`, `textarea`, `select`, `checkbox`, `radio`).
- **Required** — обязательность.
- **Placeholder** — подсказка внутри поля.
- **Options** — варианты для `select/checkbox/radio` (Value/Label).

Важно про Options:

- **Value** — то, что будет сохранено в заявку (payload).
- **Label** — то, что увидит пользователь.

Практика: делайте `Value` коротким и стабильным (латиница/underscores), а `Label` — человеческим.

### Config → Steps (многошаговая форма)

Если заполнены **Steps**, форма становится многошаговой:

- у каждого шага есть заголовок и подписи кнопок “Next/Previous”,
- у каждого шага есть собственный набор полей.

Рекомендация: если делаете многошаговую форму, поддерживайте логику “от простого к сложному”: на первом шаге — контактные данные, далее — уточняющие вопросы.

### Поля типа file и date (важные нюансы)

- **file**: при отправке формы файлы сохраняются и доступны в заявке (Leads) как вложения/превью.
- **date**: на стороне сайта значения дат обычно передаются в формате `YYYY-MM-DD`.

## Leads (Заявки)

**Назначение:** все отправленные пользователями формы (заявки). Здесь администратор видит, когда и откуда пришла заявка, какие поля были заполнены, и какие файлы прикреплены.

![Leads — список](screenshots/28-leads-index.png)

![Lead — карточка заявки (пример)](screenshots/29-lead-detail.png)

### Что смотреть в заявке

- **Form code** — по какой форме отправлено.
- **Topic** — тема заявки.
- **Source URL** — страница, с которой отправили форму.
- **Submitted at** — дата/время.
- **Payload** — значения полей (ключ → значение).
- **UTM** — маркетинговые метки (если были).

### Вложения

Если в форме есть `file`‑поля, в Payload могут отображаться:

- превью изображений,
- ссылки на скачивание файлов.

### Персональные данные

Раздел Leads обычно содержит персональные данные и файлы пользователей. Рекомендации:

- ограничьте доступ к админ‑панели только ответственным сотрудникам,
- не пересылайте скриншоты/экспорты заявок в открытых каналах,
- при необходимости используйте внутренние процедуры хранения/удаления данных.
